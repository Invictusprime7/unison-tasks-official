# AI authoring inside the Wizard launch (milestone §3, §6–8, §13, §17–19, §24, §30–31, §37)

> **SUPERSEDED FOR FRESH-LAUNCH SEQUENCING (2026-09-30):** The active authority is [App Builder Canonical Substitution](../../docs/milestones/UNISON_APP_BUILDER_CANONICAL_SUBSTITUTION_MILESTONE_2026-09-30.md). Preserve this document's structured Composer, bounded repair, protected-path and candidate-validation work, but do not implement its deterministic-baseline-first, per-page-commit or `kept-baseline` launch sequence.

## Goal
When a customer finishes the Wizard, AI designs and writes the pages as part of the launch. Each page is checked on a draft copy, saved, and shown in the live preview. Then the next page starts. The Wizard screens stay choose-only; the AI work runs in the launch process behind them. Builder chat edits after launch use the same steps, just on a smaller piece of the site.

## What the customer sees
- The Wizard finishes, and the preview opens right away with a working basic site (today's deterministic output).
- A progress line reads "Designing Home… / Services… / Gallery…". Each page swaps to its AI-designed version as soon as it passes the checks.
- If a page fails the checks even after 3 automatic repair attempts, it keeps its basic version and a short notice says so. The launch never fails because of AI.

## Flow
```text
Wizard selections
  -> plan + Stage 4b (deterministic substrate, unchanged)
  -> preflight + commit revision 1          (baseline, never-fail)
  -> NEW stage "author":
       compile ResolvedSiteDesignContext once
       for each page (Home first, then registry order):
         edge ai-code-assistant  task=site_page_author
           -> AIComposerResponse { summary, fileOps, requestedDependencies, componentDecisions }
         prepareAICandidate (draft copy + preflight + blocking gates)
         fail -> task=site_page_repair with diagnostics (max 3)
         pass -> commitMutation (source "ai-composer") -> new revision
              -> live preview updates -> next page sees committed files
  -> handoff: Builder opens on the last committed revision
```

## Work items
1. **Edge task modes.** Evolve `ai-code-assistant/orchestrator.ts` (no new endpoint): add `site_page_author`, `site_page_repair`, `builder_source_edit`. Each returns the structured `AIComposerResponse` JSON, never prose or a snapshot. The prompt gets the page brief from the design context (page role, art direction, industry, experience, preferred and forbidden vocabulary, creative authority), plus the current committed files for the page, shared chrome, route map, component catalog and prior page summaries. Protected files are refused on the server too.
2. **Contract mirror.** A shared `AIComposerResponse` schema, byte-mirrored between client and edge, following the existing contract-mirror rule.
3. **Repair loop (`aiRepairLoop.ts`).** Author → `prepareAICandidate` → on failure, send the gate diagnostics back with "repair only failing files; keep narrative, art direction and valid files". Up to 3 attempts. The loop is shared by launch and Builder.
4. **Site authoring orchestrator (`siteAuthoringOrchestrator.ts`).** Handles page-by-page ordering, context building and per-page commits through `commitMutation`. It reports progress callbacks and keeps the last known good page on failure. Shared chrome goes to `/src/project-components/site/` on the first page, and later pages reuse it.
5. **Launch stage "author".** Added to `launchOrchestrator.ts` after the baseline commit and before handoff. It is a thin call into the orchestrator. It can degrade but never fail the run, and it uses the existing `run.degrade` channel. Handoff reads the final committed revision.
6. **Stage 4b guard.** Theme recompiles (restyle, `recompileFromPlayground`) may rewrite `index.css`/tokens only. They must never overwrite files with an `ai-composer` commit in their history. This is enforced by a check in the preflight merge.
7. **Builder uses the same loop.** The WebBuilder apply path (already on `prepareAICandidate`) calls the edge in `builder_source_edit` mode through `aiRepairLoop`, so a failing edit gets automatic repairs instead of an immediate refusal.
8. **Rules/memory.** Update the wizard selection-only memory: the Wizard UI stays selection-only, and AI authoring is allowed only through the launch "author" stage and the shared candidate transaction. Record the decision in `AGENTS.md`.

## Technical notes
- No new VFS, snapshot format, router or registry. `commitMutation` stays the only writer, and `SiteBundleSnapshot` is regenerated by the commit.
- The model is the gateway default, called from the existing edge provider loop and streamed. It follows the gateway error rules: 402/403 pause authoring and keep the baseline site, and 429/5xx get bounded backoff.
- Design decisions stay deterministic: the page order and the context fingerprint come from the design seed. The AI output is recorded in revisions, not re-derived.
- Tests: repair loop (pass, repair-then-pass, give up after 3), orchestrator (per-page commit, failure keeps baseline), launch stage never fails the run, Stage 4b guard.
